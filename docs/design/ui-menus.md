## 視覺方向（D29）

| 項目 | 內容 |
|---|---|
| 主題 | 直式像素風打磚塊（Android）。玩家用擋板接到金球或黑球後，要從 3 個道具中選 1 個，選到的立刻生效；金球是好事、黑球是壞事，玩家要看懂「這是什麼、會怎樣」 |
| 色彩 | 面板底 `K`（與 UI 區同色）；金球框用黃色階 `A B Y C D`；黑球框用 D21 暗紫 `_ < > ,`；文字白 `W`；全部取自 D01 |
| 字型 | Cubic 11 一種字型，全部 22 px（2 倍），以大小一致取代層級；層級靠位置（名稱在上、說明在下）與顏色（名稱、說明同為 `W`，標題用金／紫） |
| 版面 | 畫面中央一塊 304×432 面板；上方標題，下方 3 個直排選項（每個 280×112） |
| 原則 | 1. 圖示、名稱、效果三者一起出現，玩家不看字也能靠圖示判斷 2. 金球與黑球「外框顏色＋標題字」兩個線索都不同，不只靠顏色 3. 選項要大、間隔要夠，避免誤觸 |

- 不用漸層、發光、統一圓角卡片；面板與選項都是直角斜面，和磚塊、擋板同一語彙
- 不用「大數字＋小標籤」；開頭放的是該球本身的圖示（**修訂，待使用者確認（2026-10-28）**：D32 的 40×40 金球、黑球，原為 D20、D21 的 16×16）
- 動態只有一個重點：入場時 3 個選項依序滑入（像抽出 3 張牌）；其餘是回應操作的回饋

   **四、觸控區與誤觸防護**

   | 項目 | 規格 | 理由 |
   |---|---|---|
   | 觸控區 | 整個選項矩形 **280×112**（比下限 44×44 大很多） | 下限依據：本遊戲內部寬 360 與常見 360 dp 寬手機相當，1 內部像素約等於 1 dp；Material 建議 48 dp、Apple 建議 44 pt，使用者規定至少 44×44。選擇不可反悔，所以給 112 高（也是為了容納最多 3 行 22 px 的說明） |
   | 選項間隔 | 8 px，不屬於任何選項（按到間隔無作用） | 兩個選項之間留死區，減少按到隔壁 |
   | 選取時機 | **手指放開（touch up）時**，且按下與放開都在同一個選項內才算選中 | 手指滑動中不會誤選；按下後發現按錯可以滑開取消 |
   | 入場鎖定 | 畫面開始出現的 0~500 ms 不接受觸控 | 球型道具是在玩家拖擋板時接到的，手指還在動；先讓玩家看到畫面再選 |
   | 多點觸控 | 只處理第一個按下的手指，其他忽略 | 避免兩指同時選兩個 |
   | 選定後 | 立刻忽略所有輸入，直到畫面關閉 | 避免連點選到第二個 |
   | Android 返回鍵／手勢 | 不關閉本畫面 | 規則是「必須 3 選 1」 |
   | UI 區暫停鈕（x 304~359、y 0~31） | 本畫面開啟期間不回應 | 避免疊畫面 |
   | 二次確認 | 無，點了就生效 | 使用者已決定（2026-10-27） |
   | 無障礙 | 見七 | |

4. [D35] HUD 格子依「獲得順序」排列、擋板長度併入同一排（新增 2026-10-28，使用者已確認（2026-10-28）：方案 C；起因：使用者新決定 ①格子不固定位置，依獲得順序 ②擋板長度格併入同一排，取消第 2 欄 ③最先獲得的在最上面，前面結束後面往上補位 ④狀態還在時再獲得同一種，位置不動）：

   **一、決定摘要（一句話）**：HUD 只有**一條排列清單**（最先獲得在最上面），7 種狀態各自「有就在清單裡、沒有就不在」；新出現的接在最後；結束的移除、後面往上補位；同一種再獲得不改位置。**版面有兩個方案（見第三節），建議方案 C。**

   **二、獲得順序規則**

   - 「狀態種類」共 7 種：強化、fever、速度（減速與加速共用 1 種）、穿透、火焰、炸彈、擋板長度
   - 「存在」的定義（程式只要判斷這個，就知道清單要不要有它）：

   | 狀態種類 | 存在條件 |
   |---|---|
   | 強化 | 強化階數 ≥ 1 |
   | fever | 球數 ≥ 50（D16） |
   | 速度（減速／加速共用） | 淨階數 ≠ 0（D16：加速與減速互相抵銷） |
   | 穿透、火焰、炸彈 | 限時狀態還在倒數（穿透 20、火焰 20、炸彈 10 秒，依 README），或付費附魔 |
   | 擋板長度 | 擋板長度 ≠ 85（使用者已定：回到 85 不顯示，同 D34 第〇節） |

   | 編號 | 情況 | 規則 | 例 |
   |---|---|---|---|
   | R1 | 一種狀態從「不存在」變成「存在」 | 算新獲得，**接在清單最後** | 清單 [火焰、強化]，撿到炸彈 → [火焰、強化、炸彈] |
   | R2 | 一種狀態從「存在」變成「不存在」 | 從清單移除，後面的**往上補位**；日後再出現算新獲得（R1） | 火焰到期 → [強化、炸彈]；再撿火焰 → [強化、炸彈、火焰] |
   | R3 | 狀態還在時又獲得同一種（火焰中再撿火焰、強化再 +1、減速再降一階、時間疊加） | **位置不動**，維持第一次獲得的順序；線段條、階數照 D16 規則更新 | 清單 [火焰、強化]，再撿火焰 → 仍是 [火焰、強化] |
   | R4 | 速度淨階數歸 0 | 格子消失（D16），依 R2 移除；之後再變成非 0 算新獲得，**排到最後** | 加速 +1 在第 2 位，撿到減速 → 歸 0、移除；再撿減速 → −1 排最後 |
   | R5 | 速度方向翻轉（加速 ↔ 減速） | **只看淨階數是不是 0**：每次撿道具只差 1 階，翻轉必經過 0，所以一定是「先消失、再以新獲得排最後」（R4）；若某個效果一次跨過 0（例如一次 ±2 以上，不經過 0），格子沒有消失過，視為**同一格、位置不動**，只換圖示（SP+ ↔ SP−） | 加速 +1，一次 −2 → 減速 −1，位置不動 |
   | R6 | 擋板長度回到 85 | 格子消失（使用者已定），依 R2 移除；之後又不等於 85 算**新獲得，排最後**（與速度歸 0 一致） | 變長結束回到 85 → 移除；再撿變短 → 排最後 |
   | R7 | 擋板長度 `+` ↔ `−` 翻轉但沒經過 85（例：變長還在、再撿大幅變短，淨結果 < 85；或變長到期後剩下變短） | 長度一直 ≠ 85，視為**同一格、位置不動**，只換圖示（D34 第〇節的選圖規則不變） | `+` 變 `−`，位置不動 |
   | R8 | 付費附魔（穿透、火焰，開局就有，不倒數） | 開局清單由附魔**預先建立**，所以一定在最上面；兩種都有時依固定順序（穿透在火焰前）；附魔不會結束，永遠在原位；附魔期間再撿同種道具依 R3 位置不動 | 附魔火焰：清單 [火焰]，之後撿強化 → [火焰、強化] |
   | R9 | fever（功能還沒做，先定規則） | 當成一般「存在／不存在」狀態：球數升到 50 以上 = 新獲得（排最後），低於 50 = 移除；之後又 ≥ 50 算新獲得；不需要另外的版面規則，日後實作 fever 不必改本稿 | 球數 52 時排在清單最後；降到 40 移除 |
   | R10 | 同一幀同時獲得多個（例：金球選項一次給多個效果；撿道具造成分裂使球數 ≥ 50 而同時出現 fever） | 先處理「結束」（R2），再處理「新增」；同一幀新增的多個，依**固定順序**接在最後：強化 → fever → 速度 → 穿透 → 火焰 → 炸彈 → 擋板長度（D28 的順序，擋板長度排最後）；這個順序也用在開局清單的建立 | 同一幀獲得炸彈與強化 → 先強化、後炸彈 |
   | R11 | 狀態到期與再次獲得在同一幀 | 視為一直存在，**位置不動**（先加時間，再判斷到期） | 火焰剛好到期那幀又撿到火焰 → 位置不動 |
   | R12 | 換關、重新開始 | 清單清空；由進場時「已存在」的狀態（附魔等）依 R10 的固定順序重建（使用者已答 Q7：README 規定道具效果只持續本場遊戲，所以換關、重新開始時清單全部清空；只有付費附魔〔開局就有〕依 R10 固定順序重建） | 見 Q7 |

   - 「球的光暈」規則（D15，使用者已確認維持）：**清單中有任何一格不是「擋板長度」時才亮光暈**；只有擋板長度一格時不亮（原本寫「第 1 欄有格子」，因為取消第 2 欄，改成這個說法，行為不變）
