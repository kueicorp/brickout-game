## 視覺方向

| 項目 | 內容 |
|---|---|
| 主題 | Bricklite 直式像素打磚塊;手機高度 640~840 以上都不留黑邊、不出現大片空白,拇指好按 |
| 色彩 | 全部沿用既有色碼,本稿不新增(底 #192331、半透明黑 #000000 alpha 160、金 #F4C430、綠 #2ECC71、灰 #555D6B) |
| 字型 | 沿用 Cubic 11,字級不改 |
| 版面 | 上:資源列、返回鈕貼上緣;下:banner(活動頁)、底部列(首頁)貼下緣;中間的面板 / 內容伸縮填滿 |
| 原則 | 1. 已確認的元件尺寸、觸控 ≥44×44、字級、配色、圖片一律不動,只動「留白」與「面板高度」 2. 多出的高度優先給中間內容,不堆在上緣與內容之間 3. 640 高時與已確認的 640 版逐像素相同 |

## 共用定義(工程師照此實作)

| 名稱 | 定義 |
|---|---|
| H | 畫面高(viewport px),寬固定 360,原點左上 |
| T、B | 上、下安全區,T = max(24, 系統上方)、B = max(16, 系統下方)(沿用 README) |
| E(可伸縮高度) | E = H − T − B − 600。T=24、B=16 時 E = H − 640:640→0、780→140、800→160、840→200 |
| 為什麼是 600 | 640 版內容從 y 28 排到 banner 下緣 624,共 600;`home_layout` 已用同一個數字(`CONTENT_HEIGHT`) |
| 設計基準 | H=800、T=24、B=16 → E=160;S01、S02 的主表都是這個條件 |
| 四捨五入 | 一律「四捨五入,.5 進位」= floor(x + 0.5);用整數運算時 round(0.6E) = floor((6E + 5) ÷ 10) |
| T 偏移 | 下列所有座標是 T=24 時的值;T 不是 24 時,「上緣貼齊」的元件 y 都加 (T − 24)(見 S07) |
| 背景 | 360×840 貼下對齊,矮於 840 時裁頂部;高於 840 頂端補純色 #192331(沿用 `tall-screen.md`) |
| 比 9:16 寬 | 左右填 #192331,版面維持 360 寬置中(沿用) |
